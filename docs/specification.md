# MojiFix Specification

## 1. プロジェクト概要

MojiFixは、文字コードの変換・再解釈・Unicode解析・環境間互換性解析を行うブラウザベースのツールである。

単なる文字コード変換だけでなく、異なる環境やアプリケーション間で発生する文字化けの原因を調査できることを目的とする。

## 2. 基本方針

- ブラウザ内で処理を完結させる。
- 文字コード処理とUIを分離する。
- 複数の文字コードライブラリを共通インターフェースで扱う。
- 文字コード変換とバイト列の再解釈を区別する。
- Unicode正規化と文字コード変換を区別する。
- 変換前のバイト列を可能な限り保持する。
- OSごとの挙動を固定的に決めつけない。

## 3. 機能仕様

### 3.1 文字コード変換・再解釈

入力された文字列を指定された文字コードでバイト列に変換し、そのバイト列を別の文字コードとして解釈する。

#### 基本処理

例：

入力文字列：こんにちは

変換元：Shift_JIS

変換先：UTF-8

処理：

1. 入力文字列をShift_JISでエンコードする。
2. 生成されたバイト列を保持する。
3. バイト列をHEX形式で表示する。
4. 同一バイト列をUTF-8としてデコードする。
5. デコード結果を表示する。

```ts
const bytes = encodeText(input, sourceEncoding);
const hex = bytesToHex(bytes);
const output = decodeBytes(bytes, targetEncoding);
```

この処理は通常のテキストトランスコードではない。

**元の文字列を変換元文字コードでバイト列化し、そのバイト列を変換先文字コードとして再解釈する処理である。**

変換元と変換先が異なる場合、入力文字列と出力文字列が一致しないことがある。

#### 通常の文字コード変換との区別

通常のトランスコードは次の処理である。

```text
入力文字列
  ↓
変換元文字コードでエンコード
  ↓
バイト列
  ↓
変換元文字コードでデコード
  ↓
Unicode文字列
  ↓
変換先文字コードでエンコード
  ↓
出力バイト列
```

MojiFixの基本的な再解釈機能は、この処理とは区別する。

将来的に通常のトランスコード機能を追加する場合は、独立した機能として実装する。

### 3.2 HEX表示

変換元エンコードで生成したバイト列をHEX形式で表示する。

要件：
- 16進数で表示する。
- 2桁単位で表示する。
- 大文字・小文字の表示を選択できる設計とする。
- 空白区切りなどの表示形式を拡張可能にする。
- HEX表示と実際のバイト列を混同しない。

### 3.3 文字コード対応

初期対応候補：

- UTF-8
- Shift_JIS
- Windows-31J（CP932）
- EUC-JP
- ISO-2022-JP
- UTF-16 LE / BE

追加候補：

- Windows-1252などのWindowsコードページ
- Macintosh系文字コード
- その他のISO-8859系
- 中国語・韓国語などの文字コード

各文字コードの対応可否は、使用ライブラリとテスト結果に基づいて登録する。

### 3.4 文字コードのエイリアス

同一または関連する文字コードに複数の表記がある場合、入力時のエイリアスを正規IDに変換する。

ただし、次のような異なるマッピングは同一IDに統合しない。

- Shift_JIS
- Windows-31J（CP932）

これらは関連するが、完全に同一ではない。

### 3.5 Unicode正規化

以下の形式を扱う。

- NFC
- NFD
- NFKC
- NFKD

JavaScriptの `String.prototype.normalize()` を利用する。

正規化は明示的なユーザー操作または解析機能として実行し、基本の文字コード再解釈処理に自動で挿入しない。

### 3.6 Unicode解析

以下を解析する。

- Unicodeコードポイント
- UTF-16コードユニット
- サロゲートペア
- 異体字セレクタ
- 互換文字
- 正規化による差異

### 3.7 環境間互換性解析

Windows・macOS・iOSなどの環境間で文字表現の違いを調査する。

解析対象：

- 文字コード
- 文字のエンコード可否
- エンコード・デコード後の文字列の変化
- Unicode正規化形式
- 改行コード
- BOM
- 文字の置換・欠落

OSプリセットは代表的な設定例として提供する。

OS名だけから実際の文字コードや正規化形式を断定してはならない。

### 3.8 BOM解析

以下を対象とする。

- UTF-8 BOM
- UTF-16 LE BOM
- UTF-16 BE BOM
- UTF-32 LE BOM
- UTF-32 BE BOM

検出・付与・除去を行う。

BOMを含むバイト列を処理する場合、BOMを保持するか除去するかを明確にする。

### 3.9 改行コード解析

以下を扱う。

- CRLF
- LF
- CR

検出・変換を行う。

### 3.10 エラー・警告

次の場合は適切なエラーまたは警告を返す。

- 未対応の文字コード
- エンコード不能な文字
- 不正なバイト列
- 不正なHEX入力
- 不正な変換オプション
- 処理上限を超える入力

変換不能文字を無断で置換して成功扱いにしてはならない。

初期実装では、エンコード不能な文字は原則としてエラーにする。置換モードを追加する場合は、置換されたことを警告として明示する。

不正なバイト列のデコード結果はエンジンごとに異なる可能性があるため、実際の挙動をテストして仕様化する。

## 4. 画面仕様

### 4.1 基本画面

- 入力テキストエリア
- 変換元文字コード選択
- 変換先文字コード選択
- 変換ボタン
- HEX表示
- 変換結果表示
- コピー機能
- リセット機能

### 4.2 解析画面

将来的に以下を追加する。

- Unicode解析
- 文字コード互換性レポート
- OS別比較
- BOM解析
- 改行コード解析

## 5. 非機能要件

### 5.1 実行環境
- モダンブラウザ
- PC・タブレット・スマートフォン
- クライアントサイド処理

### 5.2 セキュリティ・プライバシー
- 入力データを外部サーバーへ送信しない。
- 変換処理はブラウザ内で行う。
- 不要な外部APIを使用しない。

### 5.3 拡張性
- 文字コードの追加が容易であること。
- エンジンを交換できること。
- Unicode解析と文字コード処理を独立させること。
- UIが内部ライブラリに依存しないこと。

## 6. 初期リリースの実装範囲

### 必須
- 文字列入力
- 文字コード選択
- バイト列生成
- HEX表示
- バイト列の再解釈
- 変換結果表示
- エラー処理

### 追加実装
- Unicode正規化
- Unicodeコードポイント表示
- BOM解析
- 改行コード解析

### 将来的な拡張
- OS互換性レポート
- Macintosh系文字コード
- 多言語文字コード
- ファイル読み込み・解析
- 通常のトランスコード機能
