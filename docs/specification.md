# MojiFix — Specification

## 1. 概要

### 1.1 アプリケーション名

MojiFix

### 1.2 目的

MojiFixは、文字コードの違いによって発生する文字化けを再現・確認するためのWebアプリケーションである。

ユーザーが入力した文字列を指定した文字コードでバイト列に変換し、そのバイト列を別の文字コードとして解釈し直すことで、文字化けの発生過程を確認できるようにする。

### 1.3 基本コンセプト

通常の文字コード変換ではなく、バイト列の再解釈を行う。

例えば、UTF-8でエンコードされた文字列をShift_JISとしてデコードすることで、本来の文字列とは異なる表示結果を再現する。

---

## 2. 基本仕様

### 2.1 変換処理

変換処理は以下の順序で行う。

1. ユーザーが文字列を入力する。
2. 変換元の文字コードを選択する。
3. 変換先の文字コードを選択する。
4. 入力文字列を変換元の文字コードでエンコードする。
5. 生成されたバイト列をHEX形式で表示する。
6. 同じバイト列を変換先の文字コードでデコードする。
7. デコード結果を画面に表示する。

### 2.2 変換例

入力：

```text
こんにちは
```

変換元：

```text
SHIFT_JIS
```

変換先：

```text
UTF-8
```

内部処理：

```text
「こんにちは」
      |
      v
SHIFT_JISでエンコード
      |
      v
バイト列
      |
      +------> HEX表示
      |
      v
UTF-8としてデコード
      |
      v
変換結果
```

重要：変換元で生成したバイト列を、変換先で直接デコードする。

変換元の文字コードで一度文字列に戻し、改めて変換先の文字コードでエンコードする処理は行わない。

### 2.3 HEX表示

生成したバイト列を16進数で表示する。

表示形式：

```text
82 B1 82 F1 ...
```

仕様：

- 1バイトにつき2桁で表示する。
- 16進数は大文字とする。
- バイト間は半角スペースで区切る。
- 実際のバイト列と表示内容を一致させる。

HEXは文字コードではなく、バイト列を表現するための形式である。

---

## 3. 対応文字コード

初期リリースでは以下の4種類に対応する。

| 内部ID | 表示名 |
|---|---|
| UTF-8 | UTF-8 |
| SHIFT_JIS | Shift_JIS |
| EUC-JP | EUC-JP |
| ISO-2022-JP | ISO-2022-JP（JIS） |

### 3.1 文字コードの追加

将来的に対応文字コードを増やせる設計とする。

文字コードの一覧はEncoding Registryで管理し、UI側に直接ハードコードしない。

### 3.2 エンコード不能文字

選択された文字コードで表現できない文字が入力された場合は、適切に処理する。

ライブラリの仕様に応じて以下のいずれかとなる。

- エラーとして変換を中断する。
- 代替文字に置換して変換を続行し、警告を表示する。

意図しない文字の置換をユーザーに知らせずに行ってはならない。

### 3.3 不正なバイト列

デコード時に不正なバイト列が存在する場合は、使用するデコーダーの仕様に従う。

置換文字（U+FFFD）が出力された場合など、必要に応じて警告を表示する。

## 4. 画面仕様

### 4.1 メイン画面

メイン画面には以下の要素を配置する。

| 要素 | 内容 |
|---|---|
| ヘッダー | アプリケーション名・ナビゲーション |
| 入力欄 | 変換対象の文字列 |
| 変換元選択 | エンコードに使用する文字コード |
| 変換先選択 | デコードに使用する文字コード |
| 変換ボタン | 変換処理を開始する |
| HEX表示欄 | 生成されたバイト列 |
| 出力欄 | デコードされた文字列 |
| コピー操作 | 入力・HEX・出力のコピー |
| リセット操作 | 入力や変換結果を初期状態に戻す |
| フッター | アプリケーション情報など |

### 4.2 入力欄

- ユーザーが任意の文字列を入力できる。
- 複数行入力に対応する。
- 入力内容を変換元文字コードでエンコードする。
- 必要に応じて入力文字数を表示する。

### 4.3 文字コード選択

- 変換元と変換先を個別に選択できる。
- 対応する文字コードを一覧から選択できる。
- 選択肢はEncoding Registryから取得する。

### 4.4 変換ボタン

- クリックすると変換処理を実行する。
- 入力が空の場合は変換しない。
- エラーが発生した場合はユーザーに通知する。

### 4.5 HEX表示欄

- 生成したバイト列をHEX形式で表示する。
- コピー操作を提供する。
- 長いバイト列でも確認できるようにする。

### 4.6 出力欄

- デコード結果を表示する。
- 読み取り専用とする。
- 文字化けした結果や置換文字も確認できるようにする。
- コピー操作を提供する。

### 4.7 リセット操作

以下の状態を初期状態に戻す。

- 入力文字列
- 変換結果
- HEX表示
- エラー・警告表示

文字コード選択も初期値に戻すかどうかは、UI設計時に統一する。

---

## 5. 初期状態

初期状態は以下とする。

| 項目 | 初期値 |
|---|---|
| 入力文字列 | 空文字列 |
| 変換元 | UTF-8 |
| 変換先 | SHIFT_JIS |
| 変換結果 | 未表示 |
| HEX | 未表示 |

初期値は実装時に変更可能だが、担当者間で統一する。

---

## 6. エラー・警告仕様

### 6.1 エラー

以下の場合にエラーを発生させる。

| エラー | 内容 |
|---|---|
| EMPTY_INPUT | 入力が空 |
| UNSUPPORTED_ENCODING | 未対応の文字コード |
| ENCODE_FAILED | エンコード失敗 |
| DECODE_FAILED | デコード失敗 |
| INVALID_REQUEST | 不正なリクエスト |
| INTERNAL_ERROR | 予期しないエラー |

### 6.2 警告

以下の場合に警告を表示する。

| 警告 | 内容 |
|---|---|
| UNMAPPABLE_CHARACTER | エンコード不能文字が存在する |
| REPLACEMENT_CHARACTER | デコード結果に置換文字が含まれる |
| POSSIBLE_DATA_LOSS | 情報が失われた可能性がある |

### 6.3 エラー表示

- エラーの内容をユーザーが理解できる表現にする。
- 内部実装の詳細やスタックトレースをそのまま表示しない。
- 必要に応じて詳細情報を開発者向けに記録する。
- エラーが発生した場合でも、すでに取得できたHEX情報などは可能な限り保持する。

---

## 7. コピー機能

以下の情報をコピーできるようにする。

- 入力文字列
- HEX
- 変換結果

コピーにはブラウザのClipboard APIを使用する。

コピーに成功した場合と失敗した場合で、ユーザーに適切なフィードバックを表示する。

---

## 8. 動作環境

### 8.1 対応環境

- PCブラウザ
- スマートフォンブラウザ
- タブレットブラウザ

### 8.2 ブラウザ内処理

文字コード変換はすべてブラウザ内で実行する。

ユーザーの入力内容を変換のために外部サーバーへ送信しない。

### 8.3 レスポンシブ対応

画面幅に応じてレイアウトを調整する。

- PC：入力・設定・結果を見やすく配置する。
- スマートフォン：縦方向のレイアウトを基本とする。
- タブレット：画面幅に応じて調整する。

---

## 9. 非機能要件

### 9.1 パフォーマンス

- 一般的な文章の変換を快適に実行できること。
- 不必要な再レンダリングを避けること。
- 大量の文字列に対する処理を考慮すること。

### 9.2 セキュリティ・プライバシー

- 入力文字列を外部サーバーへ送信しない。
- 不必要な個人情報を保存しない。
- 入力内容を永続的に保存しない。
- 表示内容をHTMLとして不必要に解釈しない。

### 9.3 保守性

- UIと変換処理を分離する。
- 文字コードの追加を容易にする。
- 共通インターフェースを維持する。
- テストを作成しやすい構造にする。

### 9.4 拡張性

将来的に以下の機能を追加できる構造とする。

- 対応文字コードの追加
- HEXからのデコード
- HEX入力機能
- 変換履歴
- 変換結果の比較
- バイト列の詳細表示

これらは初期リリースの必須機能には含めない。

## 11. 対象外機能

初期リリースでは以下を実装しない。

- ユーザーアカウント
- ログイン機能
- データベース
- サーバー側変換API
- 変換履歴の永続保存
- ファイルアップロードによる一括変換
- 外部サービスとの連携

これらは将来的な拡張候補とする。
