# B担当 開発指示書

あなたはMojiFixプロジェクトのB担当です。

# 2. 最重要仕様

MojiFixでは、変換元の文字コードでエンコードしたバイト列を、変換先の文字コードで直接デコードします。

例えば、

- 入力文字列：こんにちは
- 変換元：SHIFT_JIS
- 変換先：UTF-8

の場合、

```text
こんにちは
    ↓
SHIFT_JISでエンコード
    ↓
SHIFT_JISのバイト列
    ↓
同じバイト列をUTF-8でデコード
    ↓
変換結果
```

という処理になります。

**変換元のバイト列を変換先の文字コードでエンコードし直してはいけません。**

通常の文字コード変換と混同しないでください。

# 4. 型定義

## 4.1 EncodingId

```ts
export type EncodingId = string;
```

将来的な文字コード追加を考慮し、文字コードIDを固定的なUnion型だけで管理しないでください。

## 4.2 EncodingDefinition

```ts
export interface EncodingDefinition {
  id: EncodingId;
  label: string;
  description: string;

  capabilities: {
    encode: boolean;
    decode: boolean;
  };
}
```

## 4.3 EncodingEngine

```ts
export interface EncodingEngine {
  encode(
    text: string,
    encoding: EncodingId
  ): Uint8Array;

  decode(
    bytes: Uint8Array,
    encoding: EncodingId
  ): string;
}
```

上記のインターフェースを共通仕様として扱ってください。

関数名や引数を独自に変更しないでください。

# 5. 対応文字コード

初期実装では以下に対応してください。

| ID | 表示名 |
|---|---|
| UTF-8 | UTF-8 |
| SHIFT_JIS | Shift_JIS |
| EUC-JP | EUC-JP |
| ISO-2022-JP | ISO-2022-JP（JIS） |

それぞれについて、エンコードとデコードの両方を実装してください。

ただし、ライブラリが対応していない機能を対応済みとして扱ってはいけません。

# 6. ライブラリ選定

## 6.1 基本方針

ブラウザ上で動作する文字コード変換ライブラリを利用してください。

`TextEncoder`は標準状態ではUTF-8にしか対応しないため、Shift_JISやEUC-JPのエンコードを単純に実装してはいけません。

`TextDecoder`についても、ブラウザやエンコーディングラベルによる対応状況を確認してください。

## 6.2 確認事項

ライブラリの導入前に以下を確認してください。

- ブラウザ上で利用可能か
- TypeScriptで利用できるか
- UTF-8のエンコード・デコード
- Shift_JISのエンコード・デコード
- EUC-JPのエンコード・デコード
- ISO-2022-JPのエンコード・デコード
- 文字を表現できない場合の挙動
- 不正なバイト列のデコード時の挙動
- Next.jsの静的エクスポートとの互換性

ISO-2022-JPのエンコード対応は特に慎重に確認してください。

必要な機能を満たすライブラリが見つからない場合は、複数ライブラリの組み合わせも検討してください。

ただし、採用する前に候補と理由を報告してください。

# 7. エンコード・デコード処理

## 7.1 エンコード

```ts
encode(
  text: string,
  encoding: EncodingId
): Uint8Array
```

指定された文字コードで文字列をバイト列に変換します。

入力文字列を表現できない場合の挙動を確認し、必要に応じて警告またはエラーを返せるようにしてください。

## 7.2 デコード

```ts
decode(
  bytes: Uint8Array,
  encoding: EncodingId
): string
```

指定された文字コードとしてバイト列を解釈し、JavaScriptの文字列を返します。

デコード結果はUnicode文字列として扱います。

デコード後に別途Unicode変換を実施する必要はありません。

## 7.3 バイト列の扱い

MojiFixでは、変換元で生成したバイト列を変換先のデコードにそのまま渡します。

以下のような処理はしないでください。

```ts
// 禁止
const sourceBytes = encode(input, sourceEncoding);

const intermediateText = decode(
  sourceBytes,
  sourceEncoding
);

const targetBytes = encode(
  intermediateText,
  targetEncoding
);
```

B担当は、バイト列を正確に生成・解釈する責務を持ちます。

実際に同じバイト列を渡す処理はC担当が担当します。

# 8. ISO-2022-JPの注意事項

ISO-2022-JPは状態を持つ文字コードです。

エスケープシーケンスによって文字集合を切り替えるため、単純にバイト列を分割して個別にデコードしてはいけません。

デコード時は原則としてバイト列全体を一度に処理してください。

また、以下を確認してください。

- エスケープシーケンスの処理
- ASCIIへの復帰
- 不正なエスケープシーケンス
- 文字列末尾の状態
- エンコード後のバイト列

# 9. 文字コードレジストリ

文字コードの一覧を管理するレジストリを実装してください。

以下の機能を提供します。

```ts
registerEncoding(encoding);

getEncoding(id);

getAllEncodings();
```

## registerEncoding

文字コードを登録します。

同じIDの重複登録を防いでください。

## getEncoding

IDを指定して文字コード情報を取得します。

存在しないIDの場合は、明確なエラーを返してください。

## getAllEncodings

登録済みの文字コード一覧を取得します。

UI側がこの関数を利用して選択肢を表示できるようにしてください。

## 追加要件

文字コードの追加時に、UI側のコードを修正する必要がない設計にしてください。

# 10. エラー処理

以下のケースを考慮してください。

| 状況 | 処理 |
|---|---|
| 未対応の文字コード | エラー |
| 存在しない文字コードID | エラー |
| エンコード失敗 | エラー |
| デコード失敗 | エラー |
| 表現できない文字 | ライブラリの仕様に従い警告またはエラー |
| 不正なバイト列 | デコーダーの仕様に従い処理 |

エラーを握りつぶしてはいけません。

C担当がエラーを処理できるよう、エラーの種類や原因が分かる形で返してください。

# 11. テスト要件

最低限、以下をテストしてください。

## 11.1 同一文字コードでの往復

```ts
const bytes = encode("こんにちは", "SHIFT_JIS");

const output = decode(bytes, "SHIFT_JIS");
```

文字コードで表現可能な入力について、元の文字列と一致することを確認してください。

同様にUTF-8、EUC-JP、ISO-2022-JPも確認してください。

## 11.2 異なる文字コードでのデコード

```ts
const bytes = encode(
  "こんにちは",
  "SHIFT_JIS"
);

const output = decode(
  bytes,
  "UTF-8"
);
```

以下を確認してください。

- SHIFT_JISのバイト列が生成される。
- UTF-8デコーダーが同じバイト列を受け取る。
- 出力が入力文字列と異なっていても正常な仕様である。
- 不正なバイト列があった場合の挙動が一貫している。

## 11.3 追加テスト

- 絵文字
- 改行
- 空文字列
- 長い文字列
- 変換元で表現できない文字
- 不正なバイト列
- ISO-2022-JPのエスケープシーケンス
